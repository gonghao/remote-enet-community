## 3. 依赖与制品审查

### 3.1 实际构建范围

以 Go 1.27.3、`CGO_ENABLED=0`、`mygo_nowebview` 对 `./cmd/...` 执行离线依赖枚举：

| 目标 | 枚举包数（含标准库与项目包） | 第三方模块数 |
|---|---:|---:|
| Linux amd64 | 384 | 16 |
| Windows amd64 | 385 | 17 |
| macOS arm64 | 378 | 15 |

三目标合计 17 个不同的第三方 Go 模块。完整 module graph 为 153 个模块，不能把仅在图中或测试缓存中出现的模块当作已经链接进发布包；构建标签、角色和平台不同，实际子集也不同。

主要许可边界：

- mygo/cbor/float16/WireGuard Go 封装等有 MIT 条款。
- purego、btree、gVisor 等有 Apache-2.0 条款，gVisor 根许可还包含文件级 MIT/BSD 补充条款及 AUTHORS。
- go-text/typesetting 根许可为 `Unlicense OR BSD-3-Clause`，HarfBuzz 子目录另附 MIT；mygo 内部 shader 另附 Apache-2.0。
- yamux v0.1.2 是 MPL-2.0。已记录准确版本的源码获取地址；未来修改受覆盖文件时应一并履行相应源码义务，不能只附许可证文件。
- Pixel Code Bold 2.2 使用 SIL OFL-1.1；完整许可已在源码中存在，现加入统一索引。

完整版本与文本见 [THIRD_PARTY_NOTICES](../THIRD_PARTY_NOTICES.md) 和 [快照清单](../third_party/manifest.json)。原文保留其上游字节和摘要，新增 20 个组件的索引及 24 个许可/归属文件；这不代表每个角色都使用全部组件。

### 3.2 Wintun 单独处理

`golang.zx2c4.com/wintun` 的 MIT Go 封装与官方 `wintun.dll` 是不同制品。[Wintun 官方](https://www.wintun.net/) 将 GPLv2 源码和 ZIP 中的预编译许可分开说明。

本轮从已固定摘要的官方 0.14.1 ZIP 提取完整预编译许可，分别核对归档摘要和实际 amd64 DLL 摘要。该许可对修改、再分发和公开 API 使用有专门条件，不应标成 MIT 或简单视为无条件再许可。

若选择 AGPL 等项目许可证，源码开源与 Windows 带 DLL 二进制分发需分别评估，必要时核对是否需要额外许可；本轮不自行添加例外，也不作“必然兼容/不兼容”的未经确认结论。

### 3.3 本轮已修复的打包缺口

原打包流程只携带 Pixel Code 字体许可。现新增统一第三方通知和完整许可快照，四种桌面包均携带：

- macOS：`.app/Contents/Resources/` 中的项目 `LICENSE`、`THIRD_PARTY_NOTICES.md` 和 `third_party/`；拖动 `.app` 后仍保留通知。
- Windows：解压目录中的项目 `LICENSE`、`THIRD_PARTY_NOTICES.md` 和 `third_party/`。
- 打包检查 `go.mod`、项目 LICENSE 及每个许可快照的摘要，依赖未复核、文件缺失或内容变化时不发布包。
- 许可文件纳入现有 manifest v1 的 `files` 摘要表，不更改已有字段或业务协议。

这些修复仅补齐材料与工程门禁，不替代许可证兼容性和第三方资料发布权的确认。

## 6. 公开历史的两种方式

**建议先准备审查过的源码快照，保留现有私有研究仓库。** 新公开仓库从该快照开始，可以避免直接暴露未经许可的手册历史；这不等于删除或重写原私有主分支。

用户已确认从本地审阅快照发布到 `gonghao/remote-enet-community`。导入前不包含 `.git` 或 `docs/research/scratch/`，公开仓库独立初始化。文档中的个人域名、管理网地址、用户名和绝对路径使用示例值；历史测量数值保留，地址示例不用于实际连接。私有研究附件的引用明确标注不随快照分发，排除及转换清单由维护者私下归档。公开首提交所做的链接、发布状态和 CI 修改不改变车辆转发协议或原私有历史。

如果必须保留完整开发历史，就要先确定每个待公开提交的再分发范围，再制定单独的历史清理方案，并复核其引用和制品。现有主分支与其他工作树已经共用历史，不能在未明确决定的情况下 force push、批量删除或重写。

无论哪种方式，公开前均须完成：最终许可证与版权确认、第三方材料处理、最终源码/制品审查、构建与测试、官方发行与自建服务边界说明。仅将当前树中的文件删除，或仅给仓库添加 `.gitignore`，都不会清除已提交历史。
