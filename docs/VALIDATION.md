# 真实场景只读验收

本文件定义分层执行步骤，不代表所有项目均已通过。2026-11-18已完成公网入口/安全会话/peer-only echo及[F20实车只读验收](research/f20-readonly-2026-11-18.md)：E-Sys建连、FA/SVT/ECU读取与ISTA识别/ECU树；具体来源和边界见该报告。自动化台架见[LAB](LAB.md)，L3故障与内核弱网证据见[Wave 11](WAVE11.md)。测试身份和固定SSH命令仅用于隔离fixture，`renet-labprobe`不应拿来执行真实车辆业务。

2026-11-19已完成修正测试队列后的独立八小时双lane长稳：两lane均超过28800秒，监督器及清理通过，见[Wave 17](WAVE17.md#2026-11-19完整长稳结果)。该结果限于loopback/内存设备上的TLS/session/L3，不延伸为实车或公网持续八小时通过。

## 每次执行的共同记录

记录commit、产品角色、包内manifest/version、ZIP SHA256、OS/工具版本、本地网卡/掩码、测试拓扑、开始/结束时间、每项实际结果及未执行项。先退出旧应用，再从明确的新目录启动并核对版本；不要让旧Downloads副本承接测试。

身份、信任与GUI设置使用独立测试目录。邀请码、私钥、账号密码、真实车辆载荷不贴报告；Copy diagnostics提供白名单元数据，验收报告若含本地地址则保存在私有目录。报告缺少证据、阶段未执行或超时均不能记作通过。

## A · 实车本地对照与透明链路

需用户在场，明确车辆/工具和只读范围。车辆保持静止并具有稳定供电；本轮不执行编码、擦写、SSH使能或其它状态改变。

1. 先用同一诊断电脑本地直连，确认现有工具本身能发现车辆、识别VIN并建立诊断连接。可选择工具已支持的只读识别项目，记录真实结果，不能以假车固定VIN代替。
2. 车侧Client选择真正的ENET网卡，明确核对地址与掩码；存在多个link-local网卡时人工选择。用于LAN假车的旧en0设置需按实际网卡调整，不能让源地址漂移到上网网卡。
3. Operator选择呈现网卡并开始会话。先验证发现应答来源与端口，再重复本地对照的同一只读项目；区分“出现VIN”“诊断建连”和“完整车辆识别”。
4. 对照Root已有E-Sys/ISTA/Tool32矩阵，记录实际工具版本、入口、第一条不支持的请求或错误。Windows的工具与Operator应具备相应权限；不能通过关掉独占来掩盖未知owner。
5. 若为真实MGU，单独请求只读地址发现，核对获得的IP；仅测试已开放服务的连接，不自行开启服务。当前L3只呈现精确目标IPv4/TCP，不推定UDP、DoIP或HTTP反向回连可用。
6. 结束旧诊断连接后再测试Stop/重连；新代次的请求由用户重新发起。应用不自动重开旧隧道，不承诺故障前已经发出的请求绝未在旧连接执行。记录旧连接EOF、代次变化和新连接结果。
7. 正常退出并核对Hub/呈现端口、临时目标路由与网卡回收，保留原有路由。禁止直接删除系统link-local `/16` 来让测试通过。

## B · 真实DDNS与家庭以外网络

公司网络或手机热点均可；目标路由含tunnel接口时须结合服务端实际连接来源判定，不能仅凭访问公网域名或内网NAT回环记为WAN通过。公网入口与peer-only验收见[Wave 17](WAVE17.md)，其结果不替代完整车辆透明链路。

1. 用户准备Operator可达的DDNS和已转发TCP Hub端口。公网仅转发Hub端口（默认47000）；6801/6811发现呈现与MGU目标端口留在各自本地链路。
2. Operator的public endpoint填DDNS:端口，bind填本地呈现地址。车侧Mac的ENET网卡连车，Wi-Fi通过手机热点上网；Client的车辆源绑定仍指向ENET网卡。
3. 先从家庭以外网络连接隔离假车，完成配对、空邀请码重连、只读请求、peer-only连接测试及已有MGU路径校验。报告真实RTT/有效载荷计数与速率，不由echo指标推断单向容量、IP丢包率或编程安全性。
4. 在假车上测试切网/短时失联/停止，核对旧TCP EOF、重连退避、Direct回Disabled和显式重新启用；不在实车操作进行中随机断电模拟故障。
5. 假车WAN通过后，再按A中同一组只读项目做实车WAN对照。记录运营网络和实际异常，不把系统SSH后台基线问题直接归因于隧道。
6. 收回临时邀请、规则和监听，停止各方测试实例；确认已回收后保留私有证据。不要删除实际身份/trust文件来“恢复连接”。

## 暂不作为完成标准

本轮不以假车、内存包注入或内核netem结果替代真实工具/真实车辆结果。HTTP回连须先取得URL通告与源地址选择证据，再单独设计反向通道；签名、公证、安装与自动更新继续独立处理。
